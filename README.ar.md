# localhost_bridge — الخلاصة العربية

[![CI](https://github.com/alkhalaftech/localhost_bridge/actions/workflows/dart.yml/badge.svg)](https://github.com/alkhalaftech/localhost_bridge/actions/workflows/dart.yml) [![pub](https://img.shields.io/pub/v/localhost_bridge.svg)](https://pub.dev/packages/localhost_bridge)

> هذه **خلاصة عربية** للحزمة، وليست مرآة حرفية للمرجع. المرجع الكامل
> والعهود التفصيلية في [README.md](README.md). تغطي هذه الخلاصة نموذج
> الأمن ومرجع سياسة الأصول وعقد السلك وجدولَي دعم المتصفحات والمنصات
> بنفس العقود والأرقام، ولا تكرر: مقطع JavaScript المرجعي لجهة الصفحة،
> وقسم أداة `ArrivalGuard` المستقلة، وبعض الفقرات التفسيرية الواردة في
> المرجع الإنجليزي.

جسر HTTP محلي لـDart وFlutter: صفحات الويب وعملاء التوكن المحليون (أدوات
سطر الأوامر ووكلاء الذكاء الاصطناعي) يرسلون الأوامر إلى برنامجك؛ CORS
وإذن الشبكة المحلية وحارس إعادة ربط DNS والحدود الصارمة مضمّنة —
والجسر يفك شكل الحمولة — JSON ومفاتيح الأغلفة وعدّ العناصر والأعماق —
دون أن يفسّر الأمر، فمعناه لمعالجك وحدك.

خادمك يستمع على `127.0.0.1` حصراً (لا تعرّض للشبكة أبداً). صفحة الويب
التي يزورها المستخدم ترسل الأوامر إليه مباشرة من المتصفح؛ وبرنامج محلي
يبلغ المنفذ نفسه بتوكن وبلا متصفح. الجسر يفصل **من يملك الكلام**
و**كم يملك** — أما معنى الأوامر فيبقى كله في معالجك.

- **صفر تبعيات تشغيلية** — `dart:io` الصرفة، حزمة واحدة، بلا كود أصلي
  (قيد SDK الذي يعرضه pub.dev مجال توافق لا تبعية).
- الرفض يحمل رمز خطأ ثابتاً (`error`) — هذا عقدك البرمجي. والاستثناء
  الصادق قطعٌ فوري للاتصال: انشغال 503 (السقف العام للمقاعد وسقف
  الاتصالات المفتوحة)، ورفض حصة الأصل 503، ورفض Host برمز 403 (طلب
  ليس مضيفه عنوان هذا الجسر المحلي)، و413 الذي لا يُفرَّغ جسمه في
  حدود التفريغ — فلا يصل الرمز إلى الطرف الآخر على تلك المسارات.

## ما تحصل عليه

- استماع على `127.0.0.1` فقط، بمنفذ تختاره وبدائل تلقائية عند الانشغال.
- سياسة أصول واحدة تحكم الباب: **قائمة صريحة** (الافتراضي مغلق)، أو
  **الكل-المحصَّن** (كل أصل HTTPS صالح عبر تحصينات إلزامية)، أو
  **موافقة أول ظهور** (سؤال واحد لكل أصل جديد)، وكلها فوقها **طبقة
  توكن** أنفع للتكاملات غير المتصفحة.
- تحصينات المتصفح: أصل HTTPS صالح، و`Sec-Fetch-Mode: cors`،
  و`Sec-Fetch-Dest: empty` — توقف النماذج المخفية و`no-cors`/beacon.
- حدود موارد صارمة في كل الأوضاع: سقف جسم بالبايتات، مهلة طلب، سقف
  مقاعد متزامنة، وسقف عناصر JSON قبل الفك. والحصة لكل أصل في الدقيقة
  على مسار «الكل» (`perOriginPerMinute`) وعلى مسار القائمة معاً
  (`listedPerOriginPerMinute`، الافتراضي 120 والصفر خيار صريح = بلا
  حصة). ومن لا يرسل أصلاً دلو واحد بسقف مثله.
- صدى CORS للأصول المسموحة وحدها (أصل الطالب + `Vary: Origin`) — غير
  المسموح يُرفض قبل المعالج فلا يصل كودك، والصفحة تقرأ مثل هذا الرد
  حيثما يسري صدى CORS حصراً (رفض نافذة الموافقة ورفوض الحصة الحاملة
  `Retry-After` مقروءة بقصد).
- معرف ارتباط لكل طلب (`X-Correlation-Id`) يُردّ إليك إن كان صالحاً.
- واجهة قياس وسجل (`BridgeTelemetry`) يكيّفها المضيف فوق سجله الخاص.

## البدء السريع

ثلاثة أسطر وجسر يعمل — المضيف لا يمرر شيئاً سوى معالجه: منفذ القياس
الافتراضي يكتب التحذيرات الأمنية على stderr، ومعرّفات الارتباط تأخذ
مولّداً داخلياً عشوائياً آمناً، وإعداد «جوال» يسلّح شكل المضيف المقترَن
(التوكن مع شرط الأصل-مع-التوكن والاقتران):

```dart
import 'package:localhost_bridge/localhost_bridge.dart';

final server = LocalIntakeServer(
    onCommand: (cmd) async => const CommandOutcome(ok: true),
    protection: BridgePresets.mobile(token: generateBridgeToken()));
final port = await server.start(preferredPort: 9100);
```

وتُبدّل الحاضنة بالبديل — ‏`closed()` أو `allowList()` أو `tokenOnly()`
(الإعداد الذي يجريه الأمر التجريبي أدناه) — وكل واحد موثق في قسم
[الإعدادات الجاهزة](#الإعدادات-الجاهزة) أدناه. وبقية هذا القسم تمشي
التركيب الكامل بكل مقبض مسمى:

```dart
import 'dart:math';
import 'package:localhost_bridge/localhost_bridge.dart';

// منفذ قياس واحد يشاركه الخادم وكائن الحماية — حماية بلا منه لا تسجل
// شيئاً. هذا المنفذ يطبع أسطره: الصامت `SilentTelemetry()` يبتلع
// التحذيرات الأمنية (القفل ورفض السياسة والتوكن المتضخم) — فأبقِ منفذاً
// يطبع ما دمت تركّب الجسر.
final class _PrintTelemetry extends BridgeTelemetry {
  const _PrintTelemetry();

  @override
  void info(
    String message, {
    BridgeCategory category = BridgeCategory.network,
    Map<String, Object?>? context,
  }) {}

  @override
  void warn(
    String message, {
    BridgeCategory category = BridgeCategory.network,
    Map<String, Object?>? context,
  }) =>
      print('[warn/$category] $message');

  @override
  void error(
    String message, {
    Object? error,
    StackTrace? stackTrace,
    BridgeCategory category = BridgeCategory.network,
    Map<String, Object?>? context,
  }) =>
      print('[error/$category] $message');

  @override
  Future<T> measure<T>(
    String label,
    Future<T> Function() body, {
    Map<String, Object?>? context,
  }) =>
      body();
}

void main() async {
  const telemetry = _PrintTelemetry();

  final server = LocalIntakeServer(
    // إلزامي: معالج أوامرك — الجسر لا يفهم الحمولات.
    onCommand: (cmd) async {
      print('from ${cmd.source}: ${cmd.payloads}');
      return const CommandOutcome(ok: true);
    },
    // اختياري: منفذ القياس — الافتراضي يكتب التحذيرات الأمنية على
    // stderr أصلاً؛ وهذا المنفذ الخاص يُبقيها في سجلّك أنت (والصامت
    // يخفي الأسطر الأمنية كلياً).
    telemetry: telemetry,
    // اختياري: معرفات الارتباط — المعرف الوارد X-Correlation-Id يُكرم
    // حرفاً، والطلبات بلا معرف تأخذ معرفاً من المولد الداخلي العشوائي
    // الآمن. مرر مولدك لتشكيل المعرفات بنفسك.
    correlationIdGenerator: () =>
        '${DateTime.now().microsecondsSinceEpoch.toRadixString(16)}'
        '-${Random.secure().nextInt(1 << 32).toRadixString(36)}',
    // يخصص ميزانية المعالج (الافتراضي 30 ثانية من
    // BridgeConfig.handlerTimeout): المعالج الأطول منها يُرد بـ504
    // handler_timeout ويُحرر مقعده، وعمله المستمر يصير يتماً محسوباً،
    // وstop يُتقاعد ما تبقى عند عودتها. ولسؤال «بلا مهلة إطلاقاً»
    // مرر LocalIntakeServer.noHandlerTimeout — فnull يطلب الميزانية
    // الافتراضية من الإعدادات.
    handlerTimeout: Duration(seconds: 10),
    protection: IntakeProtection(telemetry: telemetry)
      ..update(
        policy: const OriginPolicy(
          allowed: ['https://portal.example.com', '*.partner.io'],
          // يحصر أصل مدرج مخترق بالرمز نفسه 429؛ صفر (الافتراضي) يترك
          // المدرجين بلا حصة فيظل فيضهم ماسكاً المقاعد ما دامت طلباته قائمة.
          listedPerOriginPerMinute: 120,
        ),
        // طبقة التوكن الاختيارية — أنفع للتكاملات غير المتصفحة؛ يجب
        // حفظ التوكن وتسليمه للعميل خارج النطاق (البداية السريعة تتركها،
        // وبند التوكن أدناه يفصّل حيث تستطيع الصفحة إرسال واحدة أيضاً)
      ),
  );

  final port = await server.start(preferredPort: 9100);
  print('listening on http://127.0.0.1:$port'); // المنفذ الذي أعاده start()
}
```

ومن جهة الصفحة: `POST` بـ`fetch` سادة إلى المنفذ الذي أعادته `start()` —
والمرجع لجهة الصفحة أدناه يقرأه من عنوان URL الذي فتحت به المضيفُ الصفحة،
ولا تفترض المنفذ المفضل أبداً — الخادم يرد بترويسات CORS للأصول التي أذنت
بها فحسب، وكل أصل آخر
يُرفض **قبل تشغيل معالجك**: الطلب لا يصل كودك أصلاً، والصفحة تقرأ مثل
هذا الرد حيثما يسري صدى CORS حصراً (رفض نافذة الموافقة ورفوض الحصة
الحاملة `Retry-After` مقروءة بقصد). ومن صفحة HTTPS أضف `targetAddressSpace: 'loopback'` لخيارات
الطلب — دليل Chrome لإذن الشبكة المحلية يطلبه ([دليل الشبكة المحلية](https://developer.chrome.com/docs/modern-web-guidance/guides/security/local-network-access) — تحقق 2026-11-13 وأُعيد التحقق 2026-11-15)
كي يبقى الطلب معفى من حظر المحتوى المختلط ويُفحص حيز العناوين ضد الحلقة
الراجعة بعد تحليل DNS.

إضافة التوكن لا تجعله مطلباً: ما دام أي مسار أصول يقبل (أصل مدرج، أو
«الكل-المحصَّن»، أو موافقة محفوظة)، يستطيع برنامج محلي أن يقدم ذلك
`Origin` فيعبر بلا التوكن. ولجعل التوكن **مطلباً فوق الأصل المقبول**،
فعّل `OriginPolicy.requireOriginWithToken`: الأصل المؤهل بلا توكن صالح
يقرأ `403 token_required`، والتوكن وحده — من أصل غير مؤهل أو بلا أصل
أصلاً — لا يقبل أبداً (رمز الأصل يجيب فلا يتكلم التوكن، فلا يعلم
المرسل من أصل آخر شيئاً عن توكنه). وفي هذا الوضع يعيش **الاقتران**:
المضيف يعرض رمزاً من ستة أرقام لمرة واحدة (`startPairing`، عمره 120
ثانية؛ يُعرض على شاشة المضيف نفسها أو طرفيته — الصفحة المحلية مقروءة
لكل برنامج على الجهاز فلا تحمل الرمز أبداً)، والصفحة ترسله مع أصلها
إلى `POST /pair` فتأخذ توكناً مربوطاً
بأصلها لمدة 24 ساعة — قابل للإبطال والتدوير من المضيف
(`revokePairedOrigin` / `rotatePairedOrigin`) ولا يسافر خاماً بعدها
أبداً: تثبت الصفحة حيازتها بتوقيع كل طلب (HMAC-SHA-256 فوق معرف
الاقتران وطابع ساعة الجدار والطريقة والمسار ومعرف الارتباط) في ترويسة
`X-Bridge-Pairing`. وتوقيع الصفحة بـWebCrypto سادة:

```javascript
async function signProof(tokenHex, pairingId, method, path, correlationId) {
  const stamp = Date.now(); // اجعل الطوابع فريدة: لا توقّع مرتين في ملي-ثانية
  const canonical = `v1\n${pairingId}\n${stamp}\n${method}\n${path}\n${correlationId}`;
  const keyBytes = new Uint8Array(tokenHex.match(/.{2}/g).map(h => parseInt(h, 16)));
  const key = await crypto.subtle.importKey(
      'raw', keyBytes, {name: 'HMAC', hash: 'SHA-256'}, false, ['sign']);
  const sig = await crypto.subtle.sign(
      'HMAC', key, new TextEncoder().encode(canonical));
  const sigHex = [...new Uint8Array(sig)]
      .map(b => b.toString(16).padStart(2, '0')).join('');
  return `${pairingId}.${stamp}.${sigHex}`;
}
// الترويسات: { 'X-Bridge-Pairing': proof, 'X-Correlation-Id': cid, ... }
```

توقيع مستعمل أو خارج عن دقيقة انحراف ساعة الخادم يقرأ
`403 pair_signature_replay` — وقّع طلباً جديداً ولا تزيد شيئاً: الطابع
هو الطزاجة. وبالخيار مطفأً (الافتراضي) يسلك اليوم حرفاً: التوكن مسار
مستقل اختياري، وصفحة المتصفح ترسل `X-Bridge-Token` حيثما يُجاب لها
الفحص المسبق، وعملاء المحليون بلا ترويسات لهم باب توكنهم.

وعميل التوكن المحلي لا يحتاج متصفحاً — `curl` واحد هو العميل كله.
اضبط التوكن مرة بـ`update(token: generateBridgeToken())` وسلّمه للعميل
خارج النطاق:

```bash
curl -X POST http://127.0.0.1:9100/ \
  -H 'Content-Type: application/json' \
  -H "X-Bridge-Token: $BRIDGE_TOKEN" \
  -d '{"data": ["your-command"]}'
```

## الإعدادات الجاهزة

‏`BridgePresets` يعيد كائن حماية مكتمل البناء لإحدى الحاضنات الأربع؛
وسياسة كل مصنع هي حرفاً الشكل الذي يسميه صفه، فيمكنك أن تختبر ما
شحنتَه:

| الإعداد | السياسة التي يسلسها | ما يُقبل |
|---|---|---|
| `BridgePresets.closed()` | الشكل المغلق: قائمة فارغة، لا «الكل-المحصَّن»، لا اكتشاف، الاقتران غير مسلح، لا توكن | لا شيء — كل صفحة وكل محاولة توكن تقرأ `403 origin_not_listed` |
| `BridgePresets.allowList(origins: [...])` | أصولك مخزنة بالتطبيع القائم ومطابقة ككل مدخل مدرج؛ وسائر الأبواب مطفأة | المدرجون وحدهم |
| `BridgePresets.tokenOnly(token: ...)` | السياسة تبقى مغلقة والتوكن هو الباب الوحيد؛ و`requireOriginWithToken` يبقى مطفأً (التوكن يعبر مساره المستقل) | توكن صحيح من عميل محلي بلا ترويسات؛ وسواه يقرأ رفض الأصل — والتوكن الخاطئ لا يتعلم شيئاً عن نفسه |
| `BridgePresets.mobile(token: ..., origins: [...])` | ‏`requireOriginWithToken: true` مع تسليح الاقتران (شكل المضيف المقترَن) | أصلٌ حامل إثباته: التوكن المشترك أو توقيع اقتران مربوط بالأصل؛ والأصل المؤهل بلا إثبات يقرأ `403 token_required`، والتوكن وحده لا يقبل أبداً |

ولا واحد من الأربعة يفتح «الكل-المحصَّن» ولا يسلس الاكتشاف — أوسع ما
ينتجه إعداد جاهز هو قائمة أصولك أنت. والتحقق من التوكن هو القائم: توكن
تحت أرضية 32 بايت أو فوق سقف الترويسة أو فقير التنوع يرمي وقت البناء،
فلا إعداد جاهز يسلس توكن السلك سيرفضه. و«جوال» هو إعداد انطلاق المضيف
على الجوال: يقترن الصفحات التي يخدمها، والصفحات التي يخدمها الجسر
نفسه تتأهل من تلقاء نفسها ما دام خيار الصفحات المحلية مسلحاً؛ وأي
أصول خارجية يدرجها تسير إلى جوارها.

### جرّبه في دقيقة من سطر الأوامر

‏`bin/bridge_demo.dart` يشغّل جسراً حقيقياً بإعداد «توكن فقط»: يولّد
توكنه بنفسه ويطبعه مع المنفذ الذي ربطه وسطر `curl` جاهز حامل التوكن
نفسه وطريقة الإيقاف — ثم يخدم الأوامر. ولا يقبل سوى `--port <n>`: لا
يمكن تمرير فاتح «الكل-المحصَّن» أو الاكتشاف إليه، وكل وسيط آخر يُرفض
رفضاً صاخباً قبل أي ربط:

```bash
dart bin/bridge_demo.dart              # من نسخة الحزمة نفسها
dart run localhost_bridge:bridge_demo  # من أي مشروع يعتمد الحزمة
```

و‏Ctrl+C يوقفه — المستمع يُفرَّغ ويُغلق نظيفاً (مراقبة SIGINT؛ وsigint
قابل للمراقبة على ويندوز أيضاً، بتوثيق `ProcessSignal.watch` في dart:io
— [تحقق 2026-11-22](https://api.dart.dev/stable/dart-io/ProcessSignal/watch.html)).

## نموذج الأمن — اقرأه قبل اختيار السياسة

الجسر لا يستطيع معرفة هل الموقع شرعي أم مخترق: كل ما يراه ترويسة
`Origin` (يفرضها المتصفح ويزوّرها أي برنامج محلي) وترويسات `Sec-Fetch-*`
والحمولة.

- **مغلق افتراضياً**: السياسة الفارغة ترفض كل أصل — وحاملو التوكن
  يعبرون متى ضُبط توكن، فطبقة التوكن مسار دخول مستقل لا حاجز فوق
  السياسة — آمن للشحن كما هو.
- **القائمة** توقف المواقع المجهولة، ولا توقف موقعاً مدرجاً مخترقاً.
- **الكل-المحصَّن** يقبل أي أصل HTTPS صالح عبر التحصينات (أصل، طريقة
  إرسال، حصة لكل أصل) ولا يوقف موقع HTTPS خبيثاً يستعمل `fetch` —
  اسمه صريح بفضاحته عمداً، وتحذير يسجَّل عند تفعيله.
- **موافقة أول ظهور** (`onUnknownOrigin`) تسأل برنامجك مرة واحدة لكل
  أصل جديد — الطبقة الوحيدة التي تجعل «إنسان كفل هذا الموقع» حقيقة.
  المرفوض يُتذكَّر للجلسة (تطبيق سياسة مغايرة يسحب المنح المحفوظة لا
  الرفض)، ومنحة «المرة» لا تُتذكَّر.
- **طبقة التوكن** مسار دخول مستقل لا حاجز فوق الأنماط الأخرى: التقديم
  بالتوكن الصحيح يعبر بلا ترويسات متصفح. وهي النمط الوحيد الذي يقاوم
  البرامج المحلية الأخرى. إضافة التوكن لا تجعله مطلباً: ما دام أي مسار
  أصول يقبل (أصل مدرج، أو «الكل-المحصَّن»، أو موافقة محفوظة)، يستطيع
  برنامج محلي تقديم `Origin` مدرج (الترويسة يفرضها المتصفح وتُزوَّر
  محلياً) فيعبر بلا التوكن. ولجعله مطلباً فعّل
  `OriginPolicy.requireOriginWithToken`: الأصل المؤهل يطلب توكناً صالحاً
  — السر المشترك أو توقيع اقتران مربوط بالأصل — والتوكن وحده لا يقبل من
  أصل غير مؤهل أبداً (رمز الأصل يجيب لا حكم التوكن). وشرط الأصل مع
  التوكن مع **الاقتران** هو الإعداد الذي يقبل صفحة متصفح ويقاوم
  البرامج المحلية الأخرى: تقترن الصفحة مرة برمز معروض لمرة واحدة وتمسك
  توكناً مربوطاً بأصلها، منتهياً بعد 24 ساعة، قابل الإبطال والتدوير من
  المضيف، ولا يُرسل خاماً — كل طلب يحمل توقيعه الحمسي حصرا. وبالخيار
  مطفأً (الافتراضي) تستطيع صفحة المتصفح استعمال مسار التوكن حيثما يُجاب
  لها الفحص المسبق: الأصول المدرجة والموافق عليها دائماً، وفي وضعي
  الاكتشاف و«الكل-المحصَّن» أي أصل https صالح لم يُرفض بعد.
  وعلى Android شرط الأصل مع التوكن هو الإعداد العملي لا إضافة اختيارية:
  أي تطبيق مثبت يستطيع فتح المنفذ وتقديم `Origin` مزوَّر — لكنه لا
  يستطيع التوقيع بلا سر المقترن.
- **«الموثوق» يعني المقبول لا المُعقَّم**: أمرٌ اسمه `TrustedCommand` في
  معالجك إنما استحق الاسم بعبوره قرار الأصول؛ والحمولة بداخله غير
  موثوقة بحد ذاتها (انظر البند التالي).
- **الحمولات غير موثوقة في كل الأوضاع**: معالجك يعقّمها (لجهاز عام:
  قائمة أفعال الأوامر المسموحة، ومنع أوامر الإعداد والتخزين
  والبرمجيات الثابتة) — والجسر
  يسقّف عدد عناصر JSON قبل الفك: عدّ خطي واحد للعناصر البنيوية
  (`{` و`[` و`,` خارج النصوص) ورفض بما فوق `maxJsonElements`
  (الافتراضي 10,000) برمز `payload_too_complex`، فلا يتضخم جسم صغير إلى
  مئات الميغابايت من الكائنات المفكوكة. والجسم الذي يبدأ بـ`{` أو `[`
  يُعدّ سواء كان JSON صالحاً أم لا، وغيره من النص لا يُعدّ.
- **ما تراه صفحتك حين يرفض المستخدم إذن الشبكة المحلية:** خطأ شبكة
  سادة لا يمكن تمييزه عن توقف الجسر — تعامَل معه كفشل اتصال لا كخطأ
  من أخطاء الجسر.

## مرجع سياسة الأصول

| حقل `OriginPolicy` | الأثر |
|---|---|
| `allowed` | أصول كاملة (`https://host`) — تُطابق الأصل الكامل الذي يرسله المتصفح، فالمنفذ غير الافتراضي يُكتب داخل المدخل نفسه (`https://host:8443`)، والمدخل بلا منفذ يطابق الشكل بلا منفذ حصراً (المتصفح يحذف المنافذ الافتراضية فصفحات `https://host:443` ترسل `https://host`)؛ أو مضيفات مجردة (`partner.io`) — تُطابق اسم المضيف وحده، فالمدخل المجرد يقبل المضيف على **أي منفذ**؛ أو `*.example.com` للنطاقات الفرعية حصراً (الجذر يُدرج صريحاً) وتطابق فروعها على **أي منفذ** — فمنفذ الصفحة يختاره من يخدمها، والشكلين المجرد والنطاقي يبنيان على النطاق. المجرد والنطاقي يقبلان `https` حصراً (زائد `http` المحلي تحت `allowLocalHttp`)، والأصل الكامل يحمل مخططه. |
| `allowAllHardened` | كل أصل HTTPS صالح عبر التحصينات، مع تحذير صريح عند التفعيل. |
| `allowLocalHttp` | استثناء التطوير: قبول `http://localhost` و`http://127.0.0.1`. |
| `onUnknownOrigin` | سؤال الموافقة لكل أصل جديد (`allowAlways`/`allowOnce`/`reject`/`dismissed`) — وهو الذي تعنيه الوثائق بوضع **«الاكتشاف»** كلّه: الأصل الذي لا يقبله أي قاعدة يسأل المضيف مرة واحدة عبره. لا يعطّل الطلب: يعود `origin_pending` فوراً مع `Retry-After` وتعيد الصفحة المحاولة؛ و`allowOnce` يمنح **إعادة واحدة** خلال ~30 ثانية حصراً؛ و`dismissed` يقفل السؤال بلا قرار: لا تُذكر ذاكرة ويُسأل الأصل مجدداً عند طلبه التالي. الأسئلة الجديدة بميزانية زمنية (10 في 10 دقائق): فوقها يعود `origin_pending` بلا سؤال جديد حتى يفرغ الكبار. |
| `reportOnly` | وضع الرصد للحصة وحدها: فوق الحصة يسجَّل كان-سيرفض ويُخدم؛ فحوص شكل الطلب ترفض دائماً — لا fetch شرعيا يفشلها قط. |
| `perOriginPerMinute` | حصة كل أصل في الدقيقة على مسار «الكل» (الافتراضي 30). |
| `listedPerOriginPerMinute` | حصة لكل أصل على مسار القائمة — 120/دقيقة هي المعتمدة الافتراضية (أمران متواصلان في الثانية: صفحة حقيقية ترسل أوامرها بحسب فعل المستخدم وتجلس بعيداً عن هذا الرقم، وأصل مدرج مخترق لا يستطيع طوفان المقاعد المشتركة). والصفر خيارٌ صريح يُبقي المدرجين بلا حصة. وفوق الحصة تقرأ الصفحة `429 origin_rate_limited` مع `Retry-After` الصادق. وضع المراقبة (`reportOnly`) يغطي هذه الحصة كحصة «الكل»، وإخفاق توكن يحمل أصلاً مدرجاً يُحسب على نافذته أيضاً. |
| `requireFetchMetadata` | مفعّل افتراضياً. يرفض مسارا «الكل» والاكتشاف الطلبات الخالية من `Sec-Fetch-Mode: cors` و`Sec-Fetch-Dest: empty` (`cross_site_blocked`) — فيغلق الإرسال الصامت من متصفحات بلا Fetch Metadata. عملاء التوكن بلا ترويسات لا يمسهم؛ عطّله فقط إن كنت تخدم مثلهم عبر المسارات المتصفحية. |
| `askTimeout` | أقصى عمر لنافذة موافقة صامتة (الافتراضي 60 ثانية). |
| `askFiresPerParentPerWindow` | ميزانية اختيارية على أسئلة الموافقة **الجديدة** لكل نطاق أب (الافتراضي `0` — مطفأ، والسقف العام وحده): نطاق الأب هو مضيف الأصل بلا أول مقطع (`a.b.example.com` يشترك مع `b.example.com`؛ والمضيف ذو المقطعين أو العنوان الرقمي أبٌ لنفسه)، فلهذا الأب أن يفتح في نافذة العشر دقائق هذا العدد من الأسئلة الجديدة حصراً، بجانب ميزانية العشرة العامة. السؤال فوق ميزانية أبه يجيب برمزه الخاص `429 origin_parent_rate_limited` مع `Retry-After` الصادق، لكنه لا يُطلق شيئاً ولا يستهلك من الميزانية العامة — فموقعٌ يدوّر نطاقاته الفرعية لا يستطيع أن يُجوّع سؤالَ أصلٍ آخر؛ والسقف العام يبقى برمزه `origin_pending`. والقيمة السالبة تُرمى عند `update()`. |

### بناء حوار الموافقة

حوار الموافقة الذي يعرضه مضيفك جزء من نموذج الأمن، وأربعة انضباطات تجعل
قرار الإنسان حقيقياً: اعرض المخطط والمضيف وحدهما (`https://portal.example.com`)
وأبرز الجزء القابل للتسجيل من المضيف — الأصل لا يحمل مساراً والجزء
القابل للتسجيل هو ما يستطيع المستخدم الحكم عليه فعلاً؛ بلا زر قبول
افتراضي وبانتظار قصير قبل أن تستجيب الأزرار؛ نافذة واحدة لكل أصل
(الحزمة نفسها تفتح سؤالاً واحداً لكل أصل وتلحق به الطلبات المتزامنة)؛
وأغلقها بمؤقّت مضيفك بالمدة نفسها `askTimeout` وأجب `dismissed` عند
انطلاقه. أو أغلقها من إشارة نهاية السؤال التي تصدر عن الحزمة نفسها:
اضبط `IntakeProtection.onQuestionClosed` فيُخبر المضيف مرة واحدة بالضبط
حين تنتهي نافذة السؤال (وصل الجواب، أو رمى مستقبل المضيف، أو أطبقته
مهلـة `askTimeout`)، وبالأصل المطبَّع. توقيع `onUnknownOrigin` لم يتغير؛
والسؤال الذي كبحته ميزانية الأب لم يُفتح أصلاً فلا إشارة له، و`dispose()`
تغلق الباقي بصمت.

## عقد السلك (ما تراه صفحتك)

> **`504 handler_timeout` نتيجة مجهولة لا فشل**: المعالج قد يكمل بعد
> تحرير المقعد — والإعادة العمياء قد تنفّذ الأمر مرتين. فكّك التكرار على
> `X-Correlation-Id` قبل أي إعادة (المرجع الإنجليزي يعرض التدفق كاملاً).

JSON في كل مكان: `POST` مع `Origin`، والردود تحمل `X-Correlation-Id` —
معرفك يُردّ إليك إن طابق `[A-Za-z0-9._-]` وكان طوله 128 حرفاً فأقل؛ وما
عداه يُستبدل بمعرف مولَّد.
قائمة `Access-Control-Allow-Headers` ثابتة: `Content-Type`
و`X-Bridge-Token` و`X-Correlation-Id` — يُضاف إليها `X-Bridge-Pairing`
مع تسليح الاقتران فقط، و`X-Command` مع تشغيل خيار الجسم الثنائي
`BridgeConfig.acceptBinaryBodies` فقط — فلا ترسل صفحتك ترويسة أخرى:
جواب الفحص المسبق لن يسمح بها. الأوامر تُرسل إلى `/`: في هذا الإصدار كل
مسار آخر يبلغ المعالج أيضاً — والمضيف يُنبَّه عن POST في غير الجذر —
فأرسل أوامرك إلى `/`.
رموز الأخطاء الثابتة:

| HTTP | رمز `error` | المعنى |
|---|---|---|
| 200 | — | نجاح المعالج (`{"ok":true}` — وحقل بيانات المعالج معه إن أعاد `CommandOutcome.data` وكان تحت السقف الداخلي 64KiB للصفحة؛ وفوقه تُرفض النتيجة كلها بـ`reply_data_too_large`). |
| 400 | `duplicate_header` / `origin_too_long` | ترويسة أحادية أُرسلت مرتين / ترويسة `Origin` أطول من السقف الداخلي للحزمة (1,024 محرفاً)، تُرد قبل أي معالجة. |
| 400 | `origin_malformed` / `token_too_long` / `pairing_too_long` / `bad_request` | ترويسة `Origin` ليست بالشكل `scheme://host[:port]` / ترويسة `X-Bridge-Token` فوق السقف الداخلي (1,024 بايتاً) / ترويسة `X-Bridge-Pairing` فوق السقف الداخلي (256 بايتاً، عند تسليح الاقتران فقط) / محلل HTTP رفض تأطير الطلب — كلها تُرد قبل وصول معالجك. |
| 400 | `invalid_utf8` / `empty_payload` / `unsupported_payload_shape` | الجسم ليس UTF-8 / لا حمولة صالحة / كائن JSON بلا مفاتيح أوامر معروفة. الجسم الذي يفشل فك JSON كلياً **ليس** 400 — يسقط نصاً خاماً كأمر (عقد «غير JSON يبقى خاماً» المختبَر)؛ والرقم والمنطقي و`null` يسلكون المسار الخام نفسه؛ وداخل مصفوفة JSON تسقط العناصر غير النصية والفارغة بلا إشعار. |
| 400 | `invalid_payload_item` / `malformed_json_shape` / `invalid_json` / `non_json_body` | خيارات عقد الحمولة — كلٌّ **مطفأ افتراضياً** فالسلك الافتراضي لا يجيب بها أبداً: `strictPayloadItems` ترفض قائمة JSON تحمل عنصراً غير نصي أو فارغاً (الافتراضي يسقطه صامتاً) / `requireValidJsonShape` ترفض جسماً يشبه حاوية JSON وبنيته ناقصة — فتحة بلا غالق أو سلسلة بلا نهاية (الافتراضي يسقطه نصاً خاماً) / `rejectInvalidJson` ترفض جسماً أُرسل بنوع `application/json` وفشل فك JSON / `requireJsonBodies` (وضع JSON فقط) ترفض مسار النص الخام كله — النص الخام المجرد والأجسام القياسية (رقم/منطقي/null) معاً. الأربعة تجيب قبل وصول معالجك. |
| 400 | `command_required` | مع تشغيل `BridgeConfig.acceptBinaryBodies`: جسم `application/octet-stream` بلا اسم `X-Command` — غائباً كان أو أعمى من فراغات أو بجسم فارغ: قاعدة واحدة بلا استثناء حجم (مسار النص الخام يردّ جسمه الفارغ بـ`empty_payload` بالطريقة ذاتها). الجسر لا يسلّم إلا أوامر ثنائية مسمّاة؛ والخيار مطفأً لا يمر `octet-stream` من بوابة النوع أصلاً (`415`). |
| 405 | `method_not_allowed` | المقبول `POST` (و`OPTIONS` للفحص المسبق) حصراً - وكل `GET` منها، إلا على مسارات الصفحات المحلية المسجلة والخيار `BridgeConfig.localPages` مسلّح فيها (فتلك تجيب الصفحة)، وعلى صفحة الصحة المسلحة (`BridgeConfig.healthPath`، تجيب `{"ok":true}` للأصل المقبول). |
| 403 | `origin_not_listed` / `origin_declined` / `origin_unknown` / `origin_blocked` / `origin_pending` | رفض سياسة الأصول (غير مدرج / موافقة مرفوضة / غير قابل للتأكيد / تحصين الكل / نافذة موافقة مفتوحة — أعِد بعد `Retry-After`). |
| 403 | `token_required` | الأصل تأهل لكن `OriginPolicy.requireOriginWithToken` مفعّل والطلب بلا توكن صالح (التوكن المشترك أو توقيع اقتران مربوط بالأصل) — الرفض المقروء الذي تعيد الصفحة المقترنة من بعده. |
| 403 | `pair_code_invalid` / `pair_code_expired` | على `POST /pair` (والاقتران مسلح): رمز مجهول أو مستهلك / رمز تجاوز عمره 120 ثانية. الرد يصدّى دائماً — باب الاقتران مقروء بقصد (الرمز هو البوابة لا الأصل). |
| 403 | `pair_signature_replay` | توقيع اقتران طابعه استُعمل من قبل، أو جاء خارج نافذة انحراف الساعة المقبولة (دقيقة واحدة) — الطابع نفسه لا يثبت مرتين. وقّع طلباً جديداً. |
| 403 | `cross_site_blocked` | تحصين طريقة الإرسال: `Sec-Fetch-Mode` ليس `cors`. |
| 403 | `blocked_by_protection` | رفض سلطات المضيف (دفاع إعادة ربط DNS). |
| 408 | `request_timeout` | الجسم لم يصل في وقته. |
| 413 | `payload_too_large` / `payload_too_complex` / `reply_data_too_large` | الجسم تجاوز سقف البايتات (الافتراضي 1MiB) / جسم JSON تجاوز سقف العناصر (الافتراضي 10,000 عنصر بنيوي، يُعدّ قبل الفك) / الأمر نجح لكن بيانات `CommandOutcome.data` فوق السقف الداخلي للصفحة (64KiB بعد ترميز JSON) — النتيجة كلها تُرفض بلا قصّ، والأمر يبقى منفذاً. |
| 415 | `unsupported_media_type` | جسم POST يحمل `Content-Type` خارج `BridgeConfig.allowedContentTypes` (الافتراضي `application/json` و`text/plain` — يغطي عملاء JSON والبوابات النصية؛ والغياب يمر لتكاملات المقابس الخام). أنواع نماذج HTML المخفية (`application/x-www-form-urlencoded` و`multipart/form-data`) تُرفض. الفحص بعد قبول المدخل، فمن ترفضه سياسة الأصل يرى رفض الأصل لا 415. انتبه: `text/plain` نفسه ترميزُ نماذج HTML صالح فيمر من هذه البوابة — صدُّ النماذج المتصفحية الفعلي بتحصين طريقة الإرسال (`cross_site_blocked`)، و`OriginPolicy.requireFetchMetadata` يمدّه للطلبات بلا الترويسات. مع تشغيل `BridgeConfig.acceptBinaryBodies` يدخل `application/octet-stream` الأنواع المسموحة: بايتات الجسم الخام تصل معالجك في `TrustedCommand.binaryPayload` (قائمة `payloads` تبقى فارغة؛ واسم الأمر في ترويسة `X-Command` داخل `TrustedCommand.headers`) تحت السقف الداخلي للجسم الثنائي — ثابت 256KiB لا خيار؛ وفوقه يُرد `413 payload_too_large` باسم السقف الثنائي، والجسم الثنائي بلا اسم `X-Command` (اسمٌ أعمى أو جسمٌ فارغ سواء) يُرد `400 command_required`. |
| 429 | `origin_rate_limited` / `token_locked` | نفاد حصة الأصل / محاولات توكن **خاطئة** كثيرة في آخر 60 ثانية من هذا الأصل — ميزانية التخمين الخاطئ 5 محاولات في النافذة (محاولات بلا أصل تشارك نافذة واحدة). والميزانية إشارةٌ عن التخمين الخاطئ لا رفضٌ للمرسل المتحقق منه: التوكن الصحيح يُقارن ويُقبَل أياً كان تاريخ الإخفاقات، والمطابقة تصفر النافذة. |
| 429 | `origin_parent_rate_limited` | على مسار الاكتشاف حصراً (مع ضبط `OriginPolicy.askFiresPerParentPerWindow`): ميزانية أسئلة نطاق الأب الجديدة قد نفدت — يُرفض الطلب بلا فتح سؤال موافقة، فلا يُطلق شيئاً ولا يستهلك من الميزانية العامة التي يبقى رمزها `origin_pending` كما هو. و`Retry-After` الصادق يحمل بقايا نافذة الأب. |
| 429 | `pair_budget_exceeded` | على `POST /pair` (والاقتران مسلح): خمس محاولات رمز خاطئة لكل جلسة اقتران قد استُوعبت — و`Retry-After` الصادق يحمل بقايا عمر الجلسة المعروضة. الميزانية لكل جلسة لا لكل أصل. |
| 503 | `server_busy` / `origin_seat_limit` / `protection_disposed` | المقاعد ممتلئة (المقاعد والمعالجات المتجاوزة مهلتها وما زالت تعمل ميزانية واحدة للعمل الحي) / أصل واحد يمسك حصته الكاملة من المقاعد والخادم ما زال فيه واسعاً (انظر `BridgeConfig.maxSeatsPerOrigin`) / كائن الحماية أُغلق — أنشئ جديداً. |
| 504 | `handler_timeout` | معالجك تجاوز مهلته — **الأمر قد يكون نفّذ فعلاً**: عامل 504 كـ«نتيجة مجهولة» وفكّك التكرار بمعرف الارتباط قبل الإعادة — الصفحة ترسل معرفها بنفسها (`X-Correlation-Id`) ويعود كما هو عند الإعادة؛ أما المعرف الذي يولده الخادم فلا تسوية عليه إذا ضاع الرد. |
| 500 | `internal` / رمزك / `command_failed` | فشل المعالج؛ `command_failed` هو الرمز الاحتياطي حين يفشل معالجك بلا رمز (`BridgeConfig.fallbackErrorCode` يثبّت عقدك القائم). نتيجة فاشلة تحمل `CommandOutcome.refusalStatus` داخل 400..499 تجيب بحالتها (خطأ عميل) مع تشغيل `BridgeConfig.acceptHandlerRefusal` فقط — والافتراضي يبقى 500، والعلامة خارج المجال تُتجاهل. نص الخطأ يُصدّى للموثوقين حصراً والرمز للجميع؛ و`BridgeConfig.maxErrorMessageLength` (0 = مطفأ) يسقّ النص على السلك إلى هذا العدد من بايتات UTF-8 على الأكثر بقصٍّ عند حدّ محرفٍ كامل (المحرف متعدد البايتات لا يُجزأ: يسقط كله) إن ضُبط. |

رموز القنوات تجيب على سلكها هي لا رداً HTTP: قناة الويب سوكيت (أدناه،
`BridgeConfig.wsPath`) تقرؤها آخر إطار JSON قبل الإغلاق (وسبب الإغلاق
يحمل الرمز الحرفي أيضاً)، والرد المتدفق (أدناه،
`BridgeConfig.allowStreamingReplies`) يقرأ `progress_data_too_large`
آخرَ إطار `event: result`. وعمود HTTP في هذه الصفوف يسمّي عائلة الفشل
نفسها التي تجيب بها الحقيقة على سلك HTTP — إنه الحالة المسجلة في
السجل لا سطر حالة يكتبه الرمز فعلاً. والرفض الواقع قبل ترقية الويب
سوكيت (سياسة الأصل وسلطة المضيف وسقوف المقاعد) ردٌّ HTTP صريح بالرموز
القائمة أعلاه — لا صفوف خاصة بالقناة له.
| HTTP | `error` code | المعنى |
|---|---|---|
| 403 | `ws_auth_timeout` / `ws_auth_invalid` | خطوة اعتماد القناة: أصل مقبول حملت رسالته الأولى اعتماداً فوق المهلة (10 ثوان) يُغلق / الرسالة الأولى ليست كائن JSON بحقل اعتماد واحد حصراً — `"token"` أو `"pairing"` لا الاثنين. المتصفح لا يرسل ترويسة توكن في مصافحة الويب سوكيت أصلاً فالاعتماد يسير بأول رسالة والمصافحة تؤجله. |
| 408 | `ws_idle_timeout` | لا رسالة وصلت خلال `BridgeConfig.idleTimeout` على القناة المفتوحة — الاتصال يُغلق ومقعده يُفرَّغ. |
| 413 | `ws_message_too_large` | رسالة واردة فوق السقف الداخلي للقناة (256 KiB، ثابت مسمّى لا خيار). طبقتان تفرضانه: رسالة بين السقف وسقف النقل (2 MiB) تحمل إطار الرفض هذا قبل الإغلاق؛ وإطار فوق سقف النقل نفسه يرفضه محول dart:io عند الطول المعلن (قبل تخزين أي بايت حمولة) ويقرأ الإغلاق نقلة النقل 1002 — الرفضُ المعدودُ المقروء عند سقف التسليم تحته، وقتلُ سقف النقل هو النقلُ نفسه يحرس الذاكرة من تلقاءه ولا يترك إطاراً معدوداً. والقناة ترفض التسليح على dart:io أقدم من 3.13 (أول إصدار تحمل ترقيته معلمة الطول): تسليح `wsPath` هناك يرمي `ArgumentError` عند البناء — القناة لا تعمل أبداً بلا سقف نقلها، ولا ترقية بلا سقف موجودة. |
| 413 | `progress_data_too_large` | الرد المتدفق: حدث تقدم فوق سقف الحدث الداخلي (64 KiB) ينهي التدفق بهذا الإطار ويشعل إشارة إلغاء الأمر ويخمد الsink — قناة الرد ماتت فالتغليف هو الطلب الصادق. |

الحمولات تصل مصفوفة نصوص أو نصاً واحداً أو أغلفة `{"data": [...]}` /
`{"payload": ...}` / `{"commands": [...]}` (`BridgeConfig.payloadWrapperKeys` — أضف مفتاح مجالك هناك إن استعملته بواباتك). داخل القائمة تسقط
العناصر غير النصية والفارغة بلا إشعار افتراضياً — و`BridgeConfig.strictPayloadItems` ترفض الطلب بدلاً من ذلك. والجسم الذي يفشل فك
JSON يسقط نصاً خاماً كأمر افتراضياً — و`BridgeConfig.rejectInvalidJson`
(على مرسلي `application/json` حصراً) و`BridgeConfig.requireJsonBodies`
(وضع JSON فقط) ترفضان تلك المسارات بدلاً منه. والحمولات المضغوطة تمر
كما هي: فك الضغط مسؤولية المضيف.

## قناتا المضيف إلى الصفحة (الرد المتدفق والويب سوكيت)

القناتان مطفأتان افتراضياً، والسلك الافتراضي مطابق بايتاً بايتاً
للإصدارات السابقة.

**الرد المتدفق** — `BridgeConfig.allowStreamingReplies: true` يتيح
لصفحةٍ أن تطلب التدفق لأمرٍ واحد بترويسة `X-Bridge-Stream: events`
(ترويسة preflight تُسمح بها مع الخيار مسلّحاً حصراً). الرد حينها
`text/event-stream`: المعالج يبلّغ تقدمه عبر `TrustedCommand.progress`
(نداء واحد = إطار `event: progress` واحد بترتيب النداءات)، ونتيجته
تعبر آخرَ إطار `event: result` بعقد الرد القائم (`{"ok":...}` — الرموز
نفسها وسقف البيانات نفسه وقواعد النص نفسها كالرد JSON). والصفحة تقرؤه
بـ `fetch` وقارئ الجسم المتدفق:

```javascript
const res = await fetch(ENDPOINT, {method: 'POST', headers: {
  'Content-Type': 'application/json', 'X-Bridge-Stream': 'events',
}, body: '["LONG-JOB"]'});
const reader = res.body.getReader();  // الإطارات: event: progress / result
```

قيمة تقدم فوق سقف الحدث الداخلي (64 KiB) تنهي التدفق
برمز `progress_data_too_large` وتشعل إشارة إلغاء الأمر؛ وإغلاق الصفحة
وسط التدفق يشعل الإشارة نفسها ولا يبقى مقعد ولا مقبس.

**قناة الويب سوكيت** — `BridgeConfig.wsPath: '/ws'` (أي مسار سوى
`/pair`) ترقّي مصافحة المتصفح عبر خطوة القبول نفسها التي يمر بها كل
طلب: الأصل وFetch Metadata وسلطة المضيف وسقوف المقاعد تجيب برموزها
القائمة قبل الترقية. والمتصفح لا يرسل ترويسات في المصافحة، فالاعتماد —
التوكن أو توقيع الاقتران — يسير بأول رسالة (كائن JSON
`{"token": "..."}` أو `{"pairing": "id.stamp.sig"}` خلال مهلة الاعتماد
عشر ثوانٍ؛ وتوقيع الاقتران يوقّع `WS` ومسار القناة ومعرّف ارتباط
تختره). وكل رسالة واردة أمرٌ بفحوص الحمولة نفسها، وكل ردٌ حدثٌ بعقد
الرد القائم. والاتصال يمسك مقعداً واحداً طوال عمره فتحد المقاعد
(`maxConcurrentRequests` و`maxSeatsPerOrigin`) الاتصالات الحية لكل
أصل كما تحدد الأوامر الحية؛ ونبضٌ يبقي المسار حياً، وصمتٌ فوق
`idleTimeout` يغلقه، والرسائل فوق السقف الداخلي 256 KiB تغلقه
(`ws_message_too_large`).

```javascript
const ws = new WebSocket('ws://127.0.0.1:' + BRIDGE_PORT + '/ws');
ws.onopen = () => {
  ws.send(JSON.stringify({token: TOKEN, correlationId: 'ws-1'}));
  ws.send(JSON.stringify(['PRINT', 'label-zpl']));
};
ws.onmessage = (e) => console.log(JSON.parse(e.data));  // حدث الرد
```

## تركيب الجسر على خادم dart:io قائم

إذا كان المضيف يشغّل خادم HTTP أصلاً وأراد الجسر على مسارٍ منه — لا
على منفذ ثانٍ — فيمرّر الطلبات التي يملكها الجسر إلى
`handleHostRequest`. المضيف يبقي خادمه وتوجيهه: الطلبات التي يمررها
حصرا هي التي تبلغ الجسر، فمسارات الخادم الأخرى لا يمسها الجسر أبداً.
وكل طلب ممرَّر يمر بالحماية القائمة كاملة — البوابات نفسها بترتيبها
نفسها كمستمع `start()` الخاص، والرموز السلكية نفسها — وكل ردٍ يُكتب
ويُقطع على المقبس المنتزع كما يفعل الخادم الخاص حرفاً. سلطات المضيف
المحلي تُبنى من منفذ خادم المضيف الذي يسمعه فعلاً (يمرَّر بـ
`hostPort`)، والجسر يتحقق بالطرف البعيد بنفسه: طلب قادم من عنوان غير
loopback يُرد `403 blocked_by_protection` من البوابة الأولى حصراً —
لا قراءة ترويسة، ولا سطر سجل، ولا صرف من ميزانية التحذير، والرفض يُعدّ
في عدّاد رموز الرفض فقط (رقم ذاكرة يعين المضيف على رؤية المحاولات؛
والإنكار صامت: الطرف البعيد لا يكتب في سجل أمن الجسر، والرفض يحمل
معرف ارتباط مولَّداً حصراً) — فربطُ
المضيف على `0.0.0.0` لا يكسر ضمانة الحزمة للحلقيّة. والطرف المطبوع
IPv4-mapped IPv6 (‏`::ffff:127.0.0.1`، وهو ما يسلّمه الربط ثنائي
الطبقة لنداء IPv4 حلقيّ) يعدُّ loopback. وسقف الاتصالات المفتوحة
(`maxOpenConnections`) يحرس مستمع الجسر الخاص فلا حقيقة يقرؤها هنا —
حلقة القبول بيد المضيف؛ وميزانية المقاعد (`maxConcurrentRequests`
و`maxSeatsPerOrigin` وسقف العمل الحي) هي الميزانية المانعة على هذا
المسار، والطلب الممرَّر أثناء طيرانه يمسك مقعده داخل فراغ `stop()`
كما على الخادم الخاص.

خادم `dart:io` واحد يقسم طلباته بين الجسر وتطبيق قائم مبني على إطار
خادم آخر — مثال توثيقي وحده، بلا اعتمادية على أي إطار:

```dart
final bridge = LocalIntakeServer(/* wiring المضيف */);
final server = await HttpServer.bind(InternetAddress.anyIPv4, 8080);
server.listen((request) async {
  if (request.uri.path == '/bridge') {
    // الجسر يجيب بالحماية الكاملة، وكل ردٍ يكتب ويُقطع على المقبس المنتزع
    await bridge.handleHostRequest(request, hostPort: server.port);
  } else {
    // التطبيق القائم يجيب مساراته بنفسه بإطاره هو؛ الجسر لا يراها
    await app.handle(request);
  }
});
```

## الصفحات المحلية (صفحة اختيارية من الذاكرة)

المضيف الذي لا واجهة له — أداة سطر أوامر أو خدمة — لا يجد مكاناً
يعرض فيه حالة الأوامر أو إعداداته. الخيار `BridgeConfig.localPages`
يسلّح الصفحات المحلية: يمرّر المضيف الصفحات من الذاكرة (مساراً،
ومحتوى، ونوع محتوى) فيُجيب `GET` على تلك المسارات وحدها بالصفحة
وترويسات أمنها. وكل `GET` لغيرها يبقى بـ`405 method_not_allowed`
القائم، و`null` — الافتراضي — يبقي الخيار مطفأً والسلك حرفاً كما هو.
ولا يُقرأ من نظام الملفات شيء أبداً: الصفحات في ذاكرة المضيف، وخدمة
مجلد من القرص ليست من هذه الحزمة. والصفحات تجيب على مستمع الجسر نفسه
حصراً — على الخادم المركّب يجيب المضيف مساراته هو، و`GET` ممرَّر
يُرد `405` كأي غير POST.

**الصفحة المحلية مقروءة لكل برنامج على الجهاز** — طلب `GET` خالص بلا
ترويسات متصفح يقرؤها — فلا يوضع فيها رمز اقتران ولا توكن ولا أي سر.
ورمز الاقتران يُعرض بقناة المضيف نفسها: شاشته، أو طرفيته، حيث يراه
الإنسان عند الجهاز وحده؛ والصفحة التي تعرضه تسلّمه لكل برنامج محلي.

كل رد صفحة يحمل CSP صارمة — لا شيء يُجلب من أي مكان إلا سكربت
الصفحة ونمطها المضمّنان، والوصل على أصل الجسر نفسه
(`connect-src 'self'`) — ومعها `X-Frame-Options: DENY` و
`Referrer-Policy: no-referrer` و`X-Content-Type-Options: nosniff`،
ولا صدى CORS عليها، فلا صفحة غريبة تقرؤها عابرةَ الأصل.

أصل الصفحة نفسه — `http://127.0.0.1:<منفذ>` و
`http://localhost:<منفذ>` للمستمع المربوط — يعبر القبول بمساره
الصريح الخاص (`IntakeAdmissionPath.bridgeOrigin`)، ولا يمرّ بوضع
allow-all أبداً. والبوابات نفسها تقيّده كأصل مدرج: فحصا طريقة
الإرسال المتصفحيتان، وحصة المعدل المدرجة، وبوابة سلطة المضيف، وسقوف
المقاعد — وتحت `OriginPolicy.requireOriginWithToken` تحتاج الصفحة
التوكن المشترك أو إثبات اقتران كأي أصل مؤهل تماماً (وباب الاقتران
يُؤهل الأصل المُخدم كذلك). وكل أصل loopback آخر — ومنفذ آخر منها —
يبقى مرفوضاً كما هو. ومسار صفحة يصادم `/pair` أو مسار قناة الويب
سوكيت، أو مسار مكرر، أو قائمة فارغة، كلها ترمي `ArgumentError` عند
بناء الخادم.

```dart
final bridge = LocalIntakeServer(
  // ... wiring المضيف ...
  config: const BridgeConfig(
    localPages: [
      BridgeLocalPage(
        path: '/status',
        content: '<!doctype html><html><body>'
            '<h1>حالة الطابعة</h1><pre id="out">idle</pre>'
            '<script>fetch("/", {method: "POST",'
            ' headers: {"Content-Type": "application/json"},'
            ' body: JSON.stringify(["STATUS"])});</script>'
            '</body></html>',
      ),
    ],
  ),
);
```

## المستمعات ودورة الحياة وصفحة الصحة

ثلاثة خيارات توسّع أين يستمع الجسر وكيف، مع ثنائية دورة حياة الجوال
وهوية المثيل. كل خيار مطفأ افتراضياً: السلك المطفأ حرفاً مطابق
للإصدارات السابقة.

**مستمع الـ`::1` الاختياري** — ‏`BridgeConfig.listenIPv6Loopback: true`
يربط مستمعاً ثانياً على `::1` (حلقة راجعة IPv6، بنمط IPv6-only حصراً —
لا ثنائي طبقة أبداً) على المنفذ نفسه، وتتوسع سلطات المضيف المحلية في
الربط نفسه بصيغتَي `[::1]:port` و`::1` المجردة: الطلب الذي يسميهما
يعبر بوابة Host ما دام ذلك المستمع مربوطاً فعلاً. ومضيف لا يستطيع ربط
`::1` (IPv6 معطل) يقول تحذيراً واحداً ويبقى يخدم على `127.0.0.1` وحده.

**مستمع مقبس يونكس الاختياري** (‏Linux وmacOS حصراً) — ‏
`BridgeConfig.unixSocketPath: "/run/myapp/bridge.sock"` يخدم HTTP على
مسار الملفات هذا أيضاً لعملاء سطر الأوامر المحليين. صلاحيات الملف
للمالك وحده (النمط 0600، تُفرَض عند الربط بأداة `/bin/chmod` النظامية
بمسارها الكامل وتُتحقق بقراءة نمط الملف الفعلي قبل خدمة أي شيء) هي
حاجز النقل، ومجلد المقبس الأب يجب أن يكون سلفاً للمالك وحده (النمط
0700): الملف يولد بصلاحيات العملية ثم يضيق لحظة بعد، فلا يولد المقبس
أبداً إلا حيث لا يعبره سوى المالك — والمجلد المتساهل يفشل البدء كله
والرسالة تسمي المجلد، وفشل chmod أو التحقق يفشله، فلا مقبس بلا حاجز
يخدم أبداً. والطلب يمر بخطوة القبول
الواحدة نفسها بلا أصل (يعبر بالتوكن وحده؛ وعميل لا يرسل بيانات جلب
المتصفح يحتاج `OriginPolicy.requireFetchMetadata: false`، مفتاح
اللا-ترويسات القائم) خلف بوابة Host ذاتها (عميل HTTP/1.1 يرسل
`Host: localhost`). ومسار محتول سلفاً (أي ملف قائم، والمقبس العالق
منهم) يفشل البدء بـ`IntakeBindException` — الحزمة لا تحذف مساراً لم
تنشئه — وملف المقبس الذي أنشأته الحزمة نفسها يُرفع عند `stop` فإعادة
البدء على المسار نفسه تعيد الربط نظيفة. وسقف الاتصالات المفتوحة يحسب
هذا المستمع أيضاً.

**مستمع TLS الاختياري** — ‏`BridgeConfig.securityContext` (سياق
`SecurityContext` جاهز يمرره المضيف) يربط مستمعات الجسر البروتوكولية —
مستمع `127.0.0.1` ومستمع الـ`::1` الاختياري — عبر
`HttpServer.bindSecure`، فيصير العنوان الذي تستعمله الصفحة
`https://127.0.0.1:<port>` (و`wss://` لقناة الويب سوكيت)، وأصل الصفحة
المحلية المُخدمة يتسلح بصيغته `https://`. هذا هو الشرط الذي تسميه
Safari وWebKit بنفسهما: فاحص المحتوى المختلط عندهما يعامل عنوان الحلقة
الراجعة على HTTP الخام بوصفه غير آمن «ما لم يُحمَّل عبر HTTPS» (انظر
جدول دعم المتصفحات أدناه). الحزمة لا تولّد شهادة ولا تثبت أو تثق
بواحدة ولا تقرأ أو تكتب أي ملف لأجل TLS: أنت تمرر سياقاً يحمل سلسلة
شهادة ومفتاحها الخاص، وثقة الجهاز بهذه الشهادة مسؤوليتك وحدك — وتثبيت
جهة إصدار محلية على جهاز قرار يُوازن بمخاطره (الجهاز سيؤمن بكل ما توقّعه
تلك الجهة، لكل تطبيق عليه، حتى تزيلها). خطوة القبول ورموز السلك
والسقوف وعقد الردود كلها بايتاً ببايت نفسها على النقلين. والخيار مطفأ
افتراضياً: بترك `securityContext` بلا قيمة يبقى كل مسار ربط حرفاً
مطابقاً والمنفذ يتكلم HTTP خاماً. وضبطه مع `unixSocketPath` يرمي
`ArgumentError` عند البناء — dart:io لا يملك ربطاً آمناً لمقبس يونكس،
ومستمع يبقى عارياً بصمت تحت خيار TLS يوعد حماية لا يوصلها. ومختبر
شاهد Safari الحقيقي على ماك تملكه: ‏`dart run
tool/safari_https_loopback_lab.dart --cert <pem> --key <pem>` (الأداة
تطبع خطواتها وتقرأ أعلامها؛ ولا تولّد شهادة ولا تثبتها).

**‏`pause()` و`resume()`** — ‏ثنائية دورة حياة الجوال: ‏`pause()` تغلق
كل مستمع مربوط تحت الفراغ الرشيق نفسه الذي تجريه `stop()` (الردود
المتوسطة تكمل، والمقاعد تُنتظر، واليتامى لميزانيتهم) وتحفظ المنفذ
المربوط؛ و`resume()` تعيد الربط على ذلك المنفذ حصراً بلا بدائل —
تحريكُ المنفذ بصمت يكسر كل عميل مثبَّت على العنوان. وإن أخذ المنفذ
طرف آخر بينما ذلك، رفضت resume بـ`IntakeBindException` تسمّي المنفذ
المحفوظ مأخوذاً، وتبقى حالة الإيقاف فيستطيع المضيف المحاولة بعد
تحرر المنفذ. وهوية المثيل تعبر الدورة بلا مسس؛ و`start()` وهي معلقة
تُلغي الإيقاف (المنفذ المحفوظ يُنسى، و`resume()` بعدها تقرأ «ليست
معلقة»). والأخطاء `StateError` عبر المستقبل المعاد بنمط `start()`.

**‏`BridgeInstanceInfo`** — ‏`server.instanceInfo` تقرأ هوية التثبيت
ما دام مستمع مربوطاً: ‏`port` (المنفذ المربوط فعلاً لا المطلوب)، و
`instanceId` ‏(32 محرف hex من عشوائي آمن، تُولد مرة لكل كائن خادم،
ثابتة عبر pause/resume وعبر أجيال stop/start)، و`protocolVersion`
‏(`BridgeInstanceInfo.bridgeProtocolVersion` — إصدار عقد السلك لا
إصدار الحزمة). و`instanceId` تبقى مقروءة وهي معلقة؛ واللقطة كاملة ترمي
`StateError` حتى يعود مستمع مربوطاً.

**صفحة الصحة** — ‏`BridgeConfig.healthPath: '/health'` تسلح مسار `GET`
على ذلك المسار حصراً. تمر بالبوابة القائمة كأي طلب — بوابتي الأصل
وHost، وسقوف المقاعد، وخطوة القبول الواحدة بتسويتها — وتجيب الأصل
المقبول وحده: الجسم حرفياً `{"ok":true}`. بلا رقم إصدار ولا عدّادات
ولا تفاصيل، فلا يمكن استعمال الصفحة لبصم المضيف. والأصل غير المقبول
يقرأ الرفض القائم بلا صدى CORS، فمتصفحٌ يتفشى لا يرى شيئاً يكشف
الجسر. والصفحة تجيب على مستمع الجسر نفسه حصراً (`GET` ممرَّر على باب
مركّب يُرد `405` كأي غير POST). ومطفأةً (الافتراضي) يجيب المسار
`405 method_not_allowed` كأي `GET`.

«صدر» تعني أن الصفحة ترسل وتقرأ الرد بعد منح المستخدم الإذن. وتحصين
طريقة الإرسال لا يعتمد على أي مطالبة — يسري حيثما وصل الطلب. ومن داخل
iframe تحتاج الصفحة إلى `allow="loopback-network"` على الوسم كي تفوّض
الصفحةُ المضيفة الإذنَ للإطار. والإطار المحمي بـ `sandbox` يعمل بأصل
معتم ترفضه سياسةُ الأصول، وفي بعض المتصفحات لا تظهر مطالبة لإطار محمي
بـsandbox؛ امنحه `allow-same-origin`.

ترويسة الإجابة القديمة للشبكة الخاصة
(`Access-Control-Allow-Private-Network`) غائبة عمداً عن كل فحص مسبق
تكتبه هذه الحزمة: التحقق الحي من الصفحات الرسمية للمزودين يوم
2026-11-22 أثبت أنه لا يوجد متصفح حالي يطلبها. دليل Chrome للوصول إلى
الشبكة المحلية يقول «DO NOT rely on deprecated Private Network Access
(PNA) preflight headers» وأن «PNA preflights were never enforced as a
blocking requirement and are not needed as a fallback» ([دليل Chrome: Local Network Access](https://developer.chrome.com/docs/modern-web-guidance/guides/security/local-network-access) — جُلبت 2026-11-22)؛ وخطة PNA وُضعت على الحجز قبل أي إجبار شاحن ([Chrome: Private Network Access on hold](https://developer.chrome.com/blog/pna-on-hold) — نُشرت 2024-10-09: «This rollout is currently on hold» و«PNA preflights are not currently enforced») وشغّل Chrome مطالبةَ إذن الوصول إلى الشبكة المحلية بديلاً عنها منذ Chrome 142 ([Chrome: Local Network Access](https://developer.chrome.com/blog/local-network-access) — نُشرت 2025-06-09: «Local Network Access replaces that effort, after PNA was put on hold»)؛ وFirefox يسأل الإذن قبل الوصول لأجهزة الشبكة المحلية والقيود مفعلة افتراضياً منذ 153.0 بلا أي ترويسة فحص مسبق ([ملاحظات إصدار Firefox 153.0](https://www.firefox.com/en-US/firefox/153.0/releasenotes/) — 2026-07-21: «Local Network Access restrictions are now enabled by default for all users» و«Firefox requires websites to request permission before connecting to devices on your local network or to apps and services on your device»)؛ وMDN لم تعد توثق الترويسة إطلاقاً — صفحة الترويسة وصفحة مفهوم Private Network Access كلتاهما أجابتا HTTP 404 يوم 2026-11-22، وصفحة [MDN: Local network access](https://developer.mozilla.org/en-US/docs/Web/Security/Defenses/Local_network_access) الحالية (آخر تعديل 2026-08-12) توثق مطالبات الإذن وحدها. وما تعذر تحقيقه من صفحات الشاحنين يومها: أي تصريح من أبل أو WebKit عن فحوص PNA — تدوينة [WebKit Features for Safari 26.2](https://webkit.org/blog/17640/webkit-features-for-safari-26-2) المجلوبة يوم 2026-11-22 لا تسمي الوصول إلى الشبكة المحلية إطلاقاً — فلا ادعاء عن Safari يحمله هذا السطر.

  (`acceptHostFeed` خلف نداء `WKScriptMessage`) بدل مستمع شبكي — وهذا
  خيار تكامل هذا المشروع نفسه لا حقيقة موثقة من شاحن، فلا سطر مصدر
  يدّعيها.

### متى تناسبك الحزمة

الجسر مبني لصفحات تقود أوامر محلية لا يُقبل فيها الإرسال الصامت أو
المعاد: أوامر لا رجعة فيها (طباعة، دفع، فتح قفل، فتح ملف، تغيير حالة
جهاز) تحتاج قبول أصول وأسئلة موافقة وحصصاً ودفترَ عدم تكرار حول كل
إرسال — `DedupLedger` مع `idempotentCommand` من الحزمة نفسها
(`example/idempotent_handler.dart` هو مشهد التوصيل). والدفتر لا يُسقط
مدخلاً حياً ليأتي بمكانه: الممتلئ
يرفض الأوامر الجديدة بنتيجة `ledger_full` حتى تستقر مدخلاته أو تنقضي.
لهذه الحالة جمع `SECURITY.md` انضباطات جهة المضيف في موضع واحد:
«Recommended setup for irreversible commands»، بمسارَي الإرسال مفصَّلين:
المرسلون غير المتصفحات يُبقون سياسة الأصول فارغة ويحملون التوكن،
وصفحة المتصفح تُقبل بأصل مدرج صريح بدلاً من التوكن (وفي وضعَي الاكتشاف
و«الكل-المحصَّن» يُجاب لها الفحص المسبق فتستعمل مساره أيضاً)؛ ولكل مسار
أثره المتبقي المدوَّن (برنامج محلي يستطيع تقديم الأصل المدرج).
أما
الأمر الآمن على التكرار وبلا عاقبة فيكفيه خادم HTTP محلي سادة — أسوار
الجسر للأوامر التي يجب ألا تعمل مرتين ولا من صفحة خاطئة.

والعنونة: الخادم يرتبط بـ `127.0.0.1` افتراضياً، فليستعمل كودُ الصفحة
`127.0.0.1` — فاسم `localhost` قد يُحل إلى `::1` (IPv6) حيث لا مستمع
إلا إذا سُلّح `BridgeConfig.listenIPv6Loopback`، وبرنامج محلي آخر
يستطيع الاستماع على `::1` بالرقم نفسه ما دام الجسر يعمل. ومستمع مقبس
اليونكس الاختياري (`BridgeConfig.unixSocketPath`) يضيف نقل ملفات
لعملاء سطر الأوامر المحليين على Linux وmacOS.

## الحدود (بقرار تصميمي)

- حلقة راجعة حصراً: ‏`127.0.0.1` افتراضياً؛ ومستمع الـ`::1` الاختياري
  (`BridgeConfig.listenIPv6Loopback`) ومستمع مقبس اليونكس الاختياري
  (`BridgeConfig.unixSocketPath`، على Linux/macOS) لا ينضمان إلا
  مسلحين — وعنوان غير حلقي أو مواجه للشبكة لا أبداً.
- نقل TLS يرث من dart:io حقيقة ما-قبل-المصافحة ويصرّح بها: عميل TCP
  يتصل بمنفذ TLS ولا يكمل المصافحة أبداً لا يحجز مقعداً ولا يصل إلى
  الخادم أصلاً — لكن dart:io لا يكشف طريقة عامة لسقف تلك النافذة،
  فالمقبس يبقى مفتوحاً في طبقة النقل حتى يغلق المستمع (ولا تلتقطه
  stop القسرية). ومضيف يخدم TLS على شبكة معادية يحمي المنفذ أمامها
  بضوابط المقابس الخاصة به.
- تعشيش JSON مسقوف في مرور ما قبل الفك نفسه (`maxJsonDepth`، الافتراضي
  32) — الأعمق يُرد ب`413 payload_too_complex` قبل `jsonDecode`.
- من يمرر منافذ بديلة ل`start()` فصفحته تقرأ المنفذ الذي **يعيده**
  `start()` — لا تفترض المفضل أبداً (برنامج بنفس الجلسة قد يحتله).
- ميزانية المعالج مشغّلة افتراضياً (`BridgeConfig.handlerTimeout`،
  30 ثانية هي الافتراض المرسل): المعالج الأطول منها يُرد بـ`504
  handler_timeout` ويُحرر مقعده، وعمله المستمر يصير يتماً محسوباً.
  و`stop({Duration? timeout})` محدودة بمهلتها حين تمرر وتعيد
  `BridgeStopReport` يسمي ما بقي يعمل، وتُتقاعد عند عودتها كل يتامى
  باقين — فإعادة التشغيل لا ترث يتامى الجيل السابق في ميزانية عملها
  الحي، وهم باقون ظاهرين في عدادات القراءة (`server.counters`:
  المقاعد، واليتامى عبر الأجيال والمتقاعدون منهم مسمّون، والرفض حسب
  رمز السلك، وعددا الشكل البروتوكولي والاقتران). وثابت
  `LocalIntakeServer.noHandlerTimeout` الصريح وحده يرفع المهلة —
  فnull يطلب الميزانية الافتراضية من الإعدادات — وتحته يبقى ستة عشر
  معالجاً عالقاً يعني أن كل مرسل تالٍ مرفوض (`503 server_busy` فوق
  السقف العام، و`503 origin_seat_limit` فوق حصته هو). ويمكن
  للمعالج أيضاً قراءة إشارة الإلغاء التعاوني
  (`TrustedCommand.cancellation`) — تشعلها الحزمة عند احتراق الميزانية
  وعند stop — ويراقب المضيف `onOrphanSettled` لكل استقرار يتيم.
- **الإتاحة** (التفصيل في [`SECURITY.md`](SECURITY.md) تحت «Availability»):
  المقاعد ميزانية واحدة محدودة (16 افتراضياً) والمهلة الكلية تحرس ما
  قبل المعالج فلا مقعد يُعاش بعدها قبل بدئه، وكل رفض مبكر يرد ثم يقطع
  فلا فيض رفوض يحتجز مقعداً، وخرائط النوافذ لكل أصل مسقوفة داخلياً بعشرة
  آلاف مدخل لكل خريطة (الأقدم إدراجاً يُطرد ومفتاح الطلب الجاري لا
  يُطرد). وحصة المدرج 120/دقيقة افتراضياً (والصفر خيار صريح)، وسقف
  مقاعد المرسل الواحد (`maxSeatsPerOrigin`، 4 من 16 افتراضياً) يمنع
  أصلاً واحداً من احتكار المقاعد — ومن لا يرسل أصلاً دلو واحد بسقف
  مثله، والـpreflight يُحسب في حصة أصله، وحصة أصل لا تخصم من مقاعد
  أصل آخر. ويبقى الصدق: صفحة «الكل-المحصَّن» مدوِّرة الأصول تستطيع
  أن تملى الدلاء المتعدية حتى السقف العام فيُجاب مرسل تالٍ `503`
  (الحصص تحد نصيب كل مرسل لا مجموعهم) — فاضبط `handlerTimeout`؛
  وذروة الذاكرة تحت تدوير الأصول محدودة بالسقوف لا بالفيض؛
  و`dart:io` نفسه لا يحد طول الترويسة الواحدة ولا عدد الاتصالات
  المفتوحة — الحزمة تسقف الترويسات التي تقرؤها حصراً (`Origin` عند
  1,024 محرفاً و`X-Bridge-Token` عند 1,024 بايتاً)، والمقاعد تحد
  الطلبات الجارية، وسقف الاتصالات المفتوحة خيار يضيفه المضيف
  (`maxOpenConnections`، مطفأ افتراضياً)، والخاملة منها تنطفئ بعد
  `idleTimeout` (60 ثانية افتراضياً).
- `BridgeConfig.extraHosts` يضيف سلطات مضيف يجيب عنها الخادم (الاسم
  المجرد يطابق `الاسم:المنفذ-المربوط` كالمدمجين). كل مدخل اسم تحت
  سيطرتك يحل إلى هذا الجهاز — الاسم غير المحلي هناك (عام كان أم
  شبكة خاصة) تنازلٌ صريح منك عن حارس إعادة ربط DNS لذلك الاسم
  وحده، والإقلاع يقوله مرة في السجل.
- السقوف والمهل تُتحقق عند بناء الخادم: قيمة غير موجبة في `BridgeConfig`
  أو في مهلة ممررة ترمي `ArgumentError` بدل رفض كل الطلبات بصمت.
- لا تفسير حمولات، لا هويات، لا ربط أجهزة، لا خزن في هذا الإصدار —
  الجسر يحمل بايتات وأحكاماً لا غير.
- موجهات إذن الوصول للشبكة المحلية تختلف بين المتصفحات؛ تحصين طريقة
  الإرسال لا يعتمد عليها.
- سلوك السلك العدائي مثبت بشهود عقد (`wire_contract_test` اختبار واحد
  يعيد أربعة عشر حالة من ملف الحالات عبر ثلاثة أنماط حماية،
  و`priority_contract_test` يعيد 300 جولة طلبات ببذرة ثابتة) —
  والملفات العشوائية الأوسع على خارطة الطريق.
- مسار المتصفح مثبت بمختبر متصفح حقيقي (`browser_lab_test`) يقود
  Chrome/Chromium النظامي بلا واجهة، بصفر اعتماديات مضافة: صفحة تحمل
  التوكن القائم ترسل أمراً وتقرأ الرد، وصفحة بلا اعتراف تُرفض بلا حكم
  مقروء بينما السلك يحمل الرمز الحرفي، والـpreflight يعلن
  `X-Bridge-Token`، وصفحة مقترنة تجري قصة الاقتران كاملة في المتصفح —
  تقترن بالرمز المعروض وتوقّع بـWebCrypto وتقرأ `200` ثم ترى التوقيع
  نفسه يُرد `pair_signature_replay` والصفحة بلا إثبات تقرأ
  `token_required`. وبلا متصفح على الجهاز يتخطى المختبر نفسه ويبيّن
  السبب؛ وCI يشغّله حيث تحمل صورة المشغّل Chrome؛ ووجهة المحاكي تشغَّل
  بـ`dart run tool/emulator_pairing_lab.dart`.
- لماذا لا TLS: على مسار المتصفح فوق الحلقة الراجعة، شهادة ذاتية
  التوقيع تدرّب المستخدمين على تجاوز التحذيرات ولا تشتري شيئاً أمام
  نموذج خصم المتصفح أعلاه؛ النقل حلقة راجعة حصراً لا يغادر الجهاز.

## الوثائق

- المثال الكامل القابل للتشغيل: `example/main.dart` (دارت صرفة، صفر
  تبعيات تشغيلية).
- الفحص الحي بالمتصفح: `dart run example/live_check.dart` ثم افتح
  العنوانين المطبوعين — توقع الأخضر كاملاً عبر `localhost` والحجوب المقصود
  عبر `127.0.0.1`. الأداة تخدم صفحة فحصها من الحلقة الراجعة وتأذن
  ل`localhost` وحده، فهي تثبت جولة CORS المحلية — وإثبات قبول أصل HTTPS
  عام يكون بفتح صفحتك المنشورة.
- وثائق الواجهة تسافر مع الحزمة على pub.dev.
